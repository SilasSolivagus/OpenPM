# Case 02: B 端后台审批流 — 多级费用/采购单审批

## 用例类型
- **端类型**：B 端（PC 管理后台工作台）
- **核心考察点**：多角色权限矩阵、条件分支路由（金额阈值）、驳回回流与加签/转交异常态

## 输入摘要
1. 员工提交费用申请单，状态流转：`草稿 -> 待直属主管审批 -> [金额 >= 50000?] -> 财务总监审批 -> 已通过`。
2. 审批人可执行操作：
   - **同意**：流转至下一节点或终态「已通过」。
   - **驳回**：必填驳回原因（>= 5 字），单据退回「已驳回」，支持申请人修改后重新提交。
   - **转交**：指定同级或上级审批人，校验被转交人不可为申请人本人。
3. 异常分支：并发审批冲突（单据已被他人处理）、无审批权限访问拦截。

## 必检断言（Assertions）
1. **PRD 结构化 (`02-draft-prd`)**：
   - 必须包含角色权限边界（申请人 / 直属主管 / 财务总监）及并发冲突异常说明。
2. **原型锚点 (`03-prd-to-wireframe-prototype`)**：
   - 审批操作区按钮（同意、驳回、转交）、驳回原因输入框、状态标签、审批记录列表均需具备 `data-comp-id` 和 `data-comp-name`。
3. **流程图拓扑 (`04-flow-canvas`)**：
   - 金额阈值判断（如 `D_AMOUNT_CHECK`）与审批结果判断（如 `D_APPROVE_RESULT`）必须为菱形 `<g data-node="D_*" data-node-type="decision">`。
   - 驳回回流连线 `<polyline>` 必须正确标注 `data-from` 与 `data-to` 指向申请人修改节点。
4. **门禁校验 (`05-flow-walkthrough`)**：
   - `python3 scripts/preflight_check.py` 必须返回退出码 `0`。
