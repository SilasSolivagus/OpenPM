# Case 01: C 端多状态强交互 — 内容发布触发人机验证

## 用例类型
- **端类型**：C 端（移动端 / 桌面端发布器浮层）
- **核心考察点**：高频状态切换、滑块/点选人机弹窗、风控分支跳转、异常兜底与组件锚点完整性

## 输入摘要
1. 用户在内容发布器点击「立即发布」。
2. 服务端前置风控检查：
   - 低风险：直接发布成功，跳转结果页。
   - 中/高风险：拦截发布并弹出人机验证弹窗（滑块拼图）。
3. 人机验证交互状态：
   - 初始态、拖拽中、校验中（Loading）、校验成功（自动续传发布）、校验失败（抖动提示并刷新题目）、连续失败 3 次锁定冷却 60s、网络超时重试。

## 必检断言（Assertions）
1. **PRD 结构化 (`02-draft-prd`)**：
   - 必须包含唯一功能点 ID（如 `F-01`、`F-02`、`F-03`）。
   - 必须显式定义「校验失败」「连续失败锁定」「接口超时」3 类异常分支。
2. **原型锚点 (`03-prd-to-wireframe-prototype`)**：
   - `.pwx-modal`（人机验证弹窗）、`.pwx-track`（滑块轨道）、`button.primary`（立即发布/重试按钮）必须全部具备 `data-comp-id` 和 `data-comp-name`。
3. **流程图拓扑 (`04-flow-canvas`)**：
   - 风控判断节点与人机校验结果判断节点必须为菱形 `<polygon>` 且包裹 `<g data-node="D_*" data-node-type="decision">`。
   - 所有 `<polyline>` 必须具备 `data-from` 和 `data-to`。
4. **门禁校验 (`05-flow-walkthrough`)**：
   - `python3 scripts/preflight_check.py` 必须返回退出码 `0`。
