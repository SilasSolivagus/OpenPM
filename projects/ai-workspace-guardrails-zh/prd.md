# 星云 AI 团队工作台 · 用量预算风控与超额加签审批（v2.4）

> **文档版本**：`v2.4` | **项目代号**：`ai-workspace-guardrails-zh` | **覆盖终端**：`Web 控制台` + `App 审批端 375px` | **状态**：待评审基线

---

## 1. 背景与核心痛点

随着企业研发与业务团队全面接入大模型推理网关（代码补全、智能客服 Agent、离线评测流水线），团队空间（Workspace）的月度 Token 消耗呈现显著的脉冲式波动：

1. **缺乏事前硬顶熔断，账单易失控**：评测脚本死循环或突发流量可在数小时内击穿月度预算，原有账单仅支持次日离线汇总，缺少秒级保护性熔断。
2. **一刀切封禁误伤核心线上业务**：当空间触及预算上限时，研发成员缺少自助化临时扩容通道；无论 `$200` 沙箱补额还是 `$800` 大促扩容均需线下人工沟通，恢复耗时长达数小时。
3. **负责人审批缺少消耗速率上下文**：空间负责人（Workspace Owner）在移动端收到加额请求时，无法直观判断该密钥属于“正常大促业务峰值”还是“异常重试死循环”。

## 3. 端到端业务流程与判断路由

### 3.1 关键判断节点定义

1. **`D_HARD_CAP`（实时消耗达 100% 硬顶？）**
   - **未触顶（`< 100%`，如 `92%` 预警期）**：在 `80%` / `90%` 水位触发企微与站内预警横幅，API 密钥保持 `[正常]` 放行，项目成员可主动发起预防性临时加额（`F_QUOTA_REQ`）。
   - **达 `100%` 且策略为「自动暂停密钥」**：网关在 `10 秒` 内对当前空间非豁免密钥返回 `HTTP 429 (workspace_hard_cap_exceeded)` 进入保护性拦截页（`F_KEY_PAUSED`），已建立的流式输出正常收尾，不影响其他独立业务空间。
2. **`D_THRESHOLD`（单次追加额度 > $500？）**
   - **`<= $500` 免审自动放行**：校验该空间当月尚未消耗免审额度后，系统在 `3 秒` 内自动调增月度上限并解除密钥限流（直达 `F_QUOTA_ACTIVE`）。
   - **`> $500` 空间负责人加签**：生成加签单（如 `#QR-20261120-08`，追加 `$800`），实时推送企微移动端审批卡片至空间负责人（`F_OWNER_APPROVAL`）。
3. **`D_OWNER_DECISION`（负责人复核结论？）**
   - **同意加额并解封（`approve`）**：空间月度硬顶即时更新为 `$2,800`（默认当月有效，次月 1 日 `00:00` 自动回落至 `$2,000` 基线），受限密钥恢复 `[正常]` 并写入审计日志（`F_QUOTA_ACTIVE`）。
   - **驳回并维持原上限（`reject`）**：保留 `$2,000` 原硬顶及当前熔断保护态，向申请人回传驳回原因（`F_REJECT_HOLD`）。

## 4. 页面功能与字段契约

### 4.1 团队额度与密钥监控总览（`p-usage-dash` / `p-app-usage-dash`）
- **三联 KPI 指标卡**：
  1. **本月已用 / 月度硬顶**：`$1,840 / $2,000`，进度条填充 `92%`，状态标签 `[预警 92%]`。
  2. **活跃 API 密钥**：`18 个`（生产环境 `7 个`、评测沙箱 `11 个`）。
  3. **待审批加额单**：`2 单`（支持一键跳转审批台）。
- **API 密钥消耗明细表**：展示密钥掩码（如 `sk-prod-...8f2a`）、绑定业务与负责人、调用模型族、本月累计消耗、实时消耗速率（`$/h`）、状态标签及快捷「扩容 / 策略」入口。

### 4.2 预算风控与超限熔断配置页（`p-guardrail-modal` / `p-app-guardrail-modal`）
- **月度硬顶金额（`policy.cap.input`）**：正整数 USD，校验下限 `>= 当前已发生消耗 ($1,840)`。
- **自动放行阈值（`policy.auto_threshold.input`）**：正整数 USD，默认 `$500`，上限不超过月度硬顶的 `50%`。
- **达到硬顶策略（`policy.strategy.select`）**：枚举 `自动暂停密钥`（默认）与 `仅发送告警`。
- **告警通道开关**：支持独立启停企微机器人分级预警（`80% / 90% / 100%`）与财务 FinOps Webhook 回调。

### 4.3 成员申请临时加额页（`p-quota-request` / `p-app-quota-request`）
- **归属项目密钥（`req.key.select`）**：下拉绑定当前空间内密钥并附带当前消耗额。
- **申请追加额度（`req.amount.input`）**：支持实时试算扩容后总额度及审批路由（`<= $500` 免审 vs `> $500` 加签）。
- **成本中心与有效期**：必选财务成本中心编码（如 `CC-204`）及额度有效期（默认仅当月账期有效，次月自动回落基线，杜绝临时扩容演变为永久超支）。
- **业务峰值事由（`req.reason.textarea`）**：必填不少于 15 字的容量测算说明。

### 4.4 空间负责人加签审批台（`p-owner-approval` / `p-app-owner-approval`）
- **消耗速率对比子表**：并列展示目标密钥与同空间生产均值在「近 24h 消耗速率」「429/5xx 重试率」「单次会话均摊成本」三个维度的对比，辅助负责人快速排除死循环异常。
- **复核动作**：必填或选填复核备注（`approve.note.textarea`），支持「同意加额并解封」（`approve.confirm.btn`）与「驳回并维持原上限」（`approve.reject.btn`），双端（Web 控制台与手机 375px 企微审批端）状态实时同步。

### 4.5 额度耗尽熔断拦截页（`p-key-paused`）与生效结果页（`p-quota-active`）
- **熔断拦截说明**：明确公示受影响密钥列表及错误码 `workspace_hard_cap_exceeded`，同时承诺跨业务空间物理隔离（不影响其他独立结算空间），提供「一键发起紧急加额」自愈入口。
- **额度生效与审计回执**：展示调增后水位（`$1,840 / $2,800 [66%]`）、次月自动回落规则以及包含「发起申请 → 加签通过 → 密钥解封」完整时间戳的不可篡改审计流水表。

## 5. 非功能与异常边界要求

- **熔断与解封时效**：流式计量延迟 `<= 5 秒`；触顶暂停与审批通过后的网关配额下发均须在 `10 秒` 内全局生效。
- **并发与幂等控制**：同一空间存在「待加签」申请单时，重复点击申请提示合并或追加备注，防止并发审批造成额度双重叠加。
- **审计合规**：所有预算硬顶修改、免审自动放行与人工加签操作均永久留存操作人、变更前后数值、成本中心与客户端 IP，支持导出 `.csv` 对账单。
