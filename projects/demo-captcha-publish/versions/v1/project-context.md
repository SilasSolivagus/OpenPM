# 项目上下文（Project Context）

## 1. 业务背景与核心目标

- **解决什么问题**：动态社区近期高频出现自动化脚本批量刷帖与异常转发行为，需要在不干扰正常用户发帖体验、不丢失用户已编辑草稿的前提下，为发布器接入云端风控分级处置与多题型人机验证能力。
- **核心指标 / 成功标准**：
  - 正常/白名单用户 **零打扰**（直接静默放行，不增加额外操作步骤）。
  - 命中灰名单请求 100% 经过人机校验，验证通过后自动续传原发布请求，草稿保留率 100%。
  - 当日累计明确失败达到上限 `N` 次自动入黑拦截，有效遏制机器脚本撞库重试。
- **本次范围（In Scope）**：
  - 覆盖动态社区 **原创动态发布器** 与 **转发动态发布器**（进入发布器前的入口行为无变更）。
  - 未登录状态先编辑后点击发布的登录衔接与草稿保留。
  - 云端风控三级分流（直接放行 / 灰名单人机验证 / 黑名单直接拒绝）。
  - 三种随机下发验证题型（字符验证码、滑块拼图、九宫格图片）及失败重试、验证过期、网络超时、累计 `N` 次入黑与 `M` 个自然日解黑规则。
- **明确不做（Out of Scope）**：
  - 本期不改造独立账号注册与找回密码链路的人机校验组件。
  - C 端验证浮层不提供用户主动切换验证题型的入口。

## 2. 业务术语表（Glossary）

| 术语（标准称呼） | 英文 / 代码标识 | 业务定义 | 禁用别称（避免歧义） |
| :--- | :--- | :--- | :--- |
| 动态社区发布器 | `post_editor` | 用户编写原创动态或转发社区动态的编辑容器，支持图文、话题与定位 | 评论框、私信框 |
| 灰名单验证 | `risk_verify` | 云端风控判定存在中度风险，需完成一次随机题型人机校验后方可继续发布 | 封号、禁言 |
| 明确失败 | `verify_fail` | 用户提交人机验证答案且云端判定校验未通过（计入当日失败次数 `N`；取消、换题、超时、过期均不计入） | 网络异常、放弃发布 |

## 3. 端形态与线框风格配置

### 3.1 目标端形态（Platforms）

- **覆盖端形态**：动态社区双端（`App 375px` 移动端 `phone` + `Web 宽屏` 桌面端 `wide`，通过 `variant_of` 参数化继承）
- **交互状态变量（Vars）**：
  - 全局变量：`platform`（`app` / `pc`）、`publish_scene`（`original` 原创动态 / `repost` 转发动态）
  - 局部题型变量：`captcha_type`（`chars` 字符验证码 / `slider` 滑块拼图 / `grid` 九宫格图片）
  - 分支判断变量：`login_state`、`login_result`、`risk_result`、`verify_result`、`fail_limit`、`abort_reason`、`publish_ok`

### 3.2 线框与视觉风格（Wireframe Style）

- **保真度**：纯中立双端线框（`wt-*` 样式体系，单文件零依赖）
- **主色调**：95% 纯黑白灰阶 `wt-*` + 5% 琥珀橙 `#D97706` 改动标引（仅用于增量节点标注，禁止引入品牌彩色皮肤）
- **设备视口尺寸**：移动端 `phone`（375px）+ Web 宽屏 `wide`（690px，验证弹窗基准宽度 360px）
- **组件锚点规范**：所有交互控件遵循 `specs/anchor-schema.md` 标注同页唯一点分 `data-comp-id` 与 `data-comp-name`。
