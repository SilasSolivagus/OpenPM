# 项目上下文（Project Context）

## 1. 业务背景与核心目标

- **解决什么问题**：v1.0 仅支持直属主管单级审批，导致大额采购（> 5 万元）缺乏财务风控把关；同时采购单被驳回后直接终止，申请人无法基于原草稿修改重提，重复填报成本高。
- **核心指标 / 成功标准**：
  - 金额 > 5 万元的采购单在直属主管初审同意后 100% 经过财务总监复核。
  - 驳回后草稿保留率 100%，驳回重提平均耗时缩短 70%。
- **本次范围（In Scope）**：
  - 所有采购单均先由直属主管初审；主管同意后进入金额阈值路由判断（`<= 5万` 直接办结通过，`> 5万` 追加财务总监复核）。
  - 无论是主管初审还是财务复核驳回，均保留原草稿状态，支持一键「重新编辑提交」。
- **明确不做（Out of Scope）**：
  - 暂不接入 ERP 自动打款与发票核销。

## 2. 业务术语表（Glossary）

| 术语（标准称呼） | 英文 / 代码标识 | 业务定义 | 禁用别称（避免歧义） |
| :--- | :--- | :--- | :--- |
| 采购单 | `procurement_order` | 员工发起的采购申请单据，包含金额、事由与当前审批状态 | 报销单、申购单 |
| 加签 | `countersign` | 在标准主管初审通过后按金额条件追加审批节点（金额 > 5 万加签财务总监复核） | 转审、抄送 |
| 驳回重提 | `reject_resubmit` | 审批驳回后保留原采购单草稿数据，允许申请人编辑修改后再次提交审批 | 作废重建、撤回 |

## 3. 端形态与线框风格配置

### 3.1 目标端形态（Platforms）

- **主端形态**：`web-admin`（企业管理后台，690px `wide` 宽屏线框视口）
- **交互状态变量（Vars）**：
  - `leader_decision`: `["approve", "reject"]`（`直属主管同意` / `直属主管驳回`）
  - `amount_tier`: `["le_50k", "gt_50k"]`（`<=5万` / `>5万`）
  - `audit_decision`: `["approve", "reject"]`（`财务复核通过` / `财务复核驳回`）

### 3.2 线框与视觉风格（Wireframe Style）

- **保真度**：纯中立 B 端企业管理后台中保真线框（`wt-*` 样式体系，单文件零依赖）
- **主色调**：95% 纯黑白灰阶 `wt-*` + 5% 琥珀橙 `#D97706` 改动标引（仅用于增量节点标注，禁止引入业务彩色皮肤）
- **设备视口尺寸**：桌面端 `wide`（690px 宽屏后台容器）
